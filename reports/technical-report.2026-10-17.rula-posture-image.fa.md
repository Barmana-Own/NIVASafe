## نتیجه اجرایی

مسیر فعال تحلیل تصویر RULA به‌علت خالی بودن تنظیم مجوز حریم خصوصی fail-closed است. علت HTTP 401 تاریخی ArvanCloud قطعی نیست: درخواست‌های قبلی با همان منبع محرمانهٔ اعتبارنامه برای کاتالوگ مدل و تحلیل متنی GPT-5-Mini پاسخ HTTP 200 داشته‌اند، اما درخواست بعدی HTTP 401 گرفته است؛ یک درخواست تصویر staging نیز پیش‌تر HTTP 401 داشته است. در این نوبت یک درخواست متنی متفاوت GPT-5-Mini ارسال شد که پس از ۱۵ ثانیه بدون پاسخ HTTP timeout شد؛ DNS، TCP/443 و TLS 1.3 موفق بودند. درخواست ردشدهٔ قبلی تکرار نشد. مسیر واقعی تصویر تا ذخیره، بازگشایی و گزارش اجرا نشد و چیزی منتشر نشد.

تنها اصلاح این نوبت محدود به مشاهده‌پذیری امن بود: شناسهٔ همبستگی سرویس‌دهنده فقط در قالب UUID با پیشوند اختیاری `req_` از خطای HTTP استخراج و به فرادادهٔ داخلی ممیزی منتقل می‌شود. متن پاسخ سرویس‌دهنده یا مقدار شبه‌توکن ذخیره نمی‌شود. این اصلاح، احراز هویت Arvan یا قابلیت بینایی را حل نمی‌کند.

## یافته‌های علت ریشه‌ای

### رفتار نسخهٔ فعال

handler فعال `POST /api/v1/rula/posture-image-analysis` پیش از فراخوانی ارائه‌دهنده، `RULA_IMAGE_PRIVACY_APPROVED_PROVIDER` را بررسی می‌کند. مقدار فعال خالی است؛ بنابراین مسیر فعلی باید پیش از inference متوقف شود. این نتیجه از پیکربندی و کد به‌دست آمده، نه از یک درخواست زندهٔ تازه. هیچ مجوزی تغییر نکرد.

### خطای تاریخی HTTP 401

گزارش فنی پیشین `reports/technical-report.2026-10-16.arvan-auth-investigation.en.md` شواهد محدود زیر را ثبت کرده است:

| آزمون | شواهد تاریخی |
|---|---|
| `GET /v1/models` | دو پاسخ HTTP 200 و سپس پاسخ HTTP 401 با همان منبع پیکربندی محافظت‌شده؛ کاتالوگ موفق شامل `GPT-5-Mini`، `GPT-4.1-Mini`، `GPT-4o-mini` و `DeepSeek-V4-Flash` بوده است |
| تکمیل متنی GPT-5-Mini | HTTP 200؛ مدل گزارش‌شده `GPT-5-Mini` و مصرف ۴۳ توکن طبق گزارش قبلی |
| درخواست تصویر staging | شناسهٔ پالایش‌شدهٔ تاریخی `b8e12c19-f17b-4c7a-9cdd-875209157873`؛ HTTP 401 از upstream، پاسخ امن برنامه `503 RULA_IMAGE_AI_UNAVAILABLE` و بدون ذخیرهٔ امتیاز |
| پاسخ تصویری جداگانه | یک درخواست از adapter مدل GPT-4.1-Mini به مرحلهٔ parse رسید اما schema پاسخ RULA را نپذیرفت؛ وضعیت/هویت دقیق مدل آن درخواست ذخیره نشده است |

این شواهد اعتبار پایدار کلید، دسترسی تصویری مدل یا قابلیت فعلی بینایی را ثابت نمی‌کند. پاسخ آخر فهرست مدل‌ها در گزارش پیشین، body یا challenge احراز هویت یا شناسهٔ upstream نداشت؛ شناسهٔ درخواست staging تنها شناسهٔ قابل‌استفاده برای پیگیری درگاه است. برای پرهیز از تکرار کور، 401 در این نوبت تکرار نشد. تفکیک کلید/دامنهٔ دسترسی، مجوز حساب/مدل، سیاست IP/منطقهٔ درگاه و ناپایداری سرویس فقط با گزارش درگاه یا پشتیبانی Arvan ممکن است.

### اختلاف نسخهٔ deployed و سورس

`ai-provider.js` فعال تحلیل تصویر RULA را با GPT-4.1-Mini و fallback به GPT-4o-mini می‌فرستد. تنظیم `.env` با نام `AI_RISK_MODEL=GPT-5-Mini` این wrapper تصویری را override نمی‌کند. سورس فعلی `backend/src/ai-provider.ts` مسیر تصویر را به ارائه‌دهندهٔ risk با مدل ثابت GPT-5-Mini وصل می‌کند و `backend/src/modules/assessments.ts` هم مجوز حریم خصوصی و هم مجوز قابلیت بینایی را می‌سنجد. artifact فعال اکتبر ۱۵ قدیمی‌تر است و در مسیر بررسی‌شده فقط gate حریم خصوصی را دارد. سورس فعلی همان runtime نیست.

کاتالوگ تاریخی Arvan فقط نشان می‌دهد نام مدل‌ها آن زمان فهرست شده بودند؛ دسترسی فعلی به inference تصویری با این شناسه‌ها را ثابت نمی‌کند. در این اجرا یک درخواست متن انجام شد اما پیش از دریافت پاسخ HTTP timeout شد؛ درخواست کاتالوگ تکرار نشد و هیچ تصویری ارسال نشد.

- **CODE FIXED:** فقط ثبت امن شناسهٔ همبستگی و آزمون‌های آن در این اجرا.

## نیاز دقیق برای ادامه

1. مالک حساب ArvanCloud باید شناسهٔ `b8e12c19-f17b-4c7a-9cdd-875209157873` را در گزارش پشتیبانی/درگاه تطبیق دهد و علت HTTP 401 را اعلام کند: scope کلید، وضعیت حساب/اعتبار، نشانی و منطقهٔ endpoint، IP policy و مجوز مدل تصویری. کلید در گفتگو/لاگ افشا یا تعویض نشود؛ در صورت ردشدن، یک credential جداگانهٔ مجاز staging از secret store تهیه شود.
2. پایگاه دادهٔ disposable staging، کاربر عادی احرازشده، تصویر مصنوعی و رضایت صریح آزمایشی فراهم شود؛ gate تصویر production بسته بماند.
3. پس از تأیید دسترسی، مدل مجاز یک‌بار آزمایش شود، پاسخ ساختاریافته واقعی اعتبارسنجی شود و مسیر بازبینی/امتیاز/ذخیره/بازگشایی/گزارش تکمیل گردد؛ انتشار فقط پس از بررسی rollback artifact مجاز است.
