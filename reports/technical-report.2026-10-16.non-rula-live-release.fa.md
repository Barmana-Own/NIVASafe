## دامنه و نتیجه

این انتشار کاندیدای فعلی فرانت‌اند و اصلاح موجود سیاست اپراتور پشتیبانی را منتشر کرد. تحلیل واقعی تصویر RULA و خطای شناخته‌شدهٔ HTTP 401 در ArvanCloud خارج از دامنه ماند. در production فقط فایل‌های استاتیک فرانت‌اند و یک ماژول کامپایل‌شدهٔ بک‌اند تغییر کردند. هیچ تغییری در پایگاه‌داده، پیکربندی، گیت امنیتی یا حریم خصوصی انجام نشد.

فرانت‌اند عمومی از `https://app.nivasafe.com` در توپولوژی تأییدشدهٔ Nginx/IIS ارائه می‌شود. سایت IIS با نام `NivaSafe-App-COM` روی پورت ۸۰۸۰ و ریشهٔ `C:\inetpub\nivasafe\app-com` قرار دارد؛ Nginx پورت‌های عمومی ۸۰ و ۴۴۳ را ارائه می‌کند. بک‌اند فعال در `C:\ProgramData\NIVASafe\releases\release-20261015-project-source-update\backend\dist` و فرایند PM2 با نام `nivasafe-api` روی loopback پورت ۵۰۴۴ اجرا می‌شود.

## علت ریشه‌ای و اصلاحات

### اندازهٔ قلم ورود موبایل

کاندیدای نخست CSS قانون media query شانزده‌پیکسلی داشت، اما اندازهٔ محاسبه‌شدهٔ ورودی ورود در سایت زنده همچنان ۱۵ پیکسل بود. قانون موجود `.login .login-card input { font-size: .9375rem; }` به‌دلیل specificity بالاتر برنده می‌شد. selector موبایل اکنون همان محدودهٔ `.login .login-card` را دارد و قانون آزمون بازگشت در `frontend/src/features/account/loginResponsive.test.ts` به‌روزرسانی شد. در Chromium زنده، ورودی‌های ورود در عرض ۳۲۰ تا ۴۱۴ پیکسل اکنون ۱۶ پیکسل هستند. رفتار فوکوس/بزرگ‌نمایی واقعی Safari بررسی نشد.

### کارت‌های داشبورد

سورس فعلی شامل span دو ستونه و کشیدگی یکسان برای ویجت‌های هم‌رده در `frontend/src/styles/management.css` است. مجموعه آزمون مؤلفه‌ای روی ارائهٔ داشبورد متمرکز است. CSS در باندل منتشرشده حضور دارد، اما داشبورد احراز هویت‌شده برای پذیرش بصری زنده در دسترس نبود.

### مجوز صندوق پشتیبانی

ماژول زنده قبلاً fallback موجود در سورس فعلی را نداشت؛ هر دو کلید `SUPPORT_OPERATOR_USER_IDS` و `SUPPORT_OPERATOR_ORGANIZATION_IDS` در runtime فعال غایب بودند و دسترسی اپراتور می‌توانست با 503 بسته شود. اصلاح پیشین `backend/src/modules/support.ts` در نبود allowlist فقط کاربر فعال و تأییدشده در پایگاه‌داده را با `globalRole=SUPER_ADMIN` و `protectedSystemAdmin=true` مجاز می‌کند. این سیاست همچنان وجود سازمان نشست را الزامی می‌کند، جست‌وجوی تیکت را در همان سازمان محدود نگه می‌دارد، فیلتر پاسخ عمومی/یادداشت داخلی و ممیزی را حفظ می‌کند و دسترسی عمومی به همهٔ مدیران ارشد نمی‌دهد. کلاینت Prisma و پایگاه‌دادهٔ موجود فیلد لازم را داشتند؛ migration لازم نبود. مقدار کلیدهای runtime چاپ یا تغییر داده نشد.

این اصلاح سورس از این انتشار قدیمی‌تر است و از فاز Debug قبلی منتقل شد؛ در این انتشار منتشر شد، نه اینکه تازه ایجاد شده باشد. آزمون‌های قبلی API/MariaDB/Chromium ایزوله در `reports/final-debug-rula-tickets.md` آمده‌اند. آن مدرک فقط staging است، نه پذیرش زندهٔ تیکت.

## امنیت و یکپارچگی داده

ورود عضو/مدیر زنده انجام نشد، دادهٔ تیکت یا ارزیابی production نوشته نشد، تصویر مشتری ارسال نشد و مقدار credential یا تنظیم runtime چاپ نشد. گیت رضایت/حریم خصوصی، نقش، tenant و یادداشت داخلی پشتیبانی دور زده نشد. migration، seed، db push، smoke تولیدی یا تغییر اعتبارنامه اجرا نشد. وابستگی اضافه یا ارتقا داده نشد. audit وابستگی production همچنان NOT RUN است.

درخواست مستقیم IIS روی پورت ۸۰۸۰ برای `/login` پاسخ 404 داد، درحالی‌که مسیر کاربر در HTTPS عمومی `/login` با 200 از مسیر proxy عمومی ارائه شد؛ تنظیمات IIS یا proxy تغییر نکرد. HTTP client پاورشل در sandbox نتوانست credential لازم برای SChannel را آماده کند؛ `curl.exe` نصب‌شده با اعتبارسنجی پیش‌فرض گواهی، بررسی‌های HTTPS عمومی را موفق انجام داد.

## ابزارها و اقدام‌های باقی‌مانده

هیچ ابزار callable از افزونه‌های Debug، UI UX Designer یا Chrome DevTools در این نشست موجود نبود (`ALL_TOOLS` موردی از آن‌ها نداشت). بررسی مرورگر با Chromium درون‌برنامه‌ای Codex و بررسی‌های shell با PowerShell/Node/Vitest انجام شد. گردش محلی Debug برای آزمون مرورگر استفاده شد؛ اجرای native plugin ادعا نمی‌شود.

برای تکمیل پذیرش غیر RULA باید با نشست‌های آزمایشی مجاز عضو و مدیر ارشد محافظت‌شده، ایجاد/پاسخ/reload تیکت، داشبورد/مدیریت/sidebar و گردش FMEA/اقدام/اعلان روی سایت زنده اجرا شود؛ Safari/WebKit روی میزبان Apple/WebKit موجود بررسی شود؛ و نسخهٔ pin شدهٔ pnpm و وابستگی نوع‌دهی توسعه در workspace غیرتولیدی کنترل‌شده بازیابی شود تا build/audit کامل بک‌اند قابل تأیید باشد. این موارد مسدودکننده‌اند، نه شواهد شکست فرانت‌اند عمومیِ منتشرشده.

بینایی RULA صریحاً به تعویق افتاده است. گزارش قبلی خطای HTTP 401 در ArvanCloud را ثبت کرده؛ در این انتشار درخواست بینایی ارسال نشد و تنظیمات provider یا رضایت تغییر نکرد.
