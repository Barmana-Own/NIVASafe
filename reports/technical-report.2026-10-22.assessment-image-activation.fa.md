## محدوده و علت ریشه‌ای

پرچم‌های خالی عملیاتی، ارسال تصویر را مستقل از رضایت حساب متوقف می‌کردند. مسیر FMEA نیز برای ارسال، بررسی مستقل رضایت و بازبینی تازه مجوز در مرز HTTP نداشت. رضایت V2 فقط هدف `rula-posture` را پوشش می‌داد؛ استفاده از آن برای FMEA مجاز فرض نشد.

معماری React/Vite، بک‌اند Fastify، Prisma/MySQL، فضای فایل حفاظت‌شده و استقرار موجود حفظ شد. نامزد انتشار از منبع منجمد انتشار قبلی ساخته و فقط تغییرات مرتبط روی آن اعمال شد. تغییرات نامرتبط موجود در checkout به‌عنوان بخشی از این انتشار معرفی نمی‌شوند.

## پیاده‌سازی و مرزهای اعتماد

فعال‌سازی عملیاتی با `RULA_IMAGE_PROCESSING_ENABLED_PROVIDER` و `FMEA_IMAGE_PROCESSING_ENABLED_PROVIDER` از ادعای تأیید شرایط حریم خصوصی ارائه‌دهنده جدا شده است. مقدار خالی صریح، حتی با وجود مقدار قدیمی تأیید، قابلیت همان روش را غیرفعال می‌کند. در پیکربندی فاقد کلید جدید، رفتار سازگار قدیمی حفظ می‌شود. قابلیت بینایی و دسترس‌پذیری ارائه‌دهنده مستقل بررسی می‌شوند. فیلدهای قدیمی تأیید حریم خصوصی در این انتشار خالی مانده‌اند.

رضایت جاری `image-processing-account-2026-10-22-v3` با هدف `assessment-images`، هر دو نوع تصویر مجاز را پوشش می‌دهد. رسیدهای V1/V2 حفظ می‌شوند و رضایت جاری محسوب نمی‌شوند. کاربر باید انتخاب خودش را دوباره ذخیره کند. مجوزهای قدیمی صاحب تصویر قابل مشاهده و قابل لغو باقی مانده‌اند و تا جایگزینی تحت سیاست جاری، وضعیت منقضی از نظر نسخه دارند.

RULA کنترل‌های حساب، صاحب تصویر، نقش، سازمان، سهمیه، نوع/امضا/حجم فایل، ذخیره یافته معتبر و بازیابی حفاظت‌شده را حفظ می‌کند. FMEA رضایت جاری و احراز هویت، سازمان، نقش و سهمیه را پیش از ارسال بررسی می‌کند. هر دو مسیر، رسید Audit شامل هش تصویر را در مرز ارسال ثبت و مجوز را تازه بررسی می‌کنند. FMEA بعد از ثبت اجباری Audit، همان رسید رضایت را دوباره تطبیق می‌دهد. خرابی ثبت اجباری یا تغییر مجوز، ارسال را متوقف می‌کند.

ارسال تصویر redirect ارائه‌دهنده را دنبال نمی‌کند و timeout به تکرار خودکار درخواست تصویری منجر نمی‌شود. تکرار محدود RULA برای پاسخ ساختاری نامعتبر، کنترل مجزای موجود است. JSON نامعتبر یا ردیف ناقص FMEA به موفقیت خالی تبدیل نمی‌شود. دستور موجود RULA برای نساختن اطلاعات غایب وظیفه، مدت، تکرار یا نیرو در نسخه منتشرشده لحاظ شده است.

## محیط مستقل، خطاها و اصلاحات

تصویر ثابت، ترسیم مصنوعی بدون شخص واقعی بود. guard درخواست فقط endpoint مشخص، مدل درخواستی، تصویر دارای هش مجاز و `redirect:error` را می‌پذیرد؛ سقف پایدار چهار تلاش کلی و دو تلاش برای هر روش است. دقیقاً دو تلاش انجام شد؛ پاسخ موفق با mock جایگزین نشد. مدل ثبت‌شده در هر دو رکورد مصرف `gpt-5-mini-2025-08-07` است. دو رسید انتقال و دو رکورد مصرف ثبت شدند؛ رزرو سهمیه باقی نماند. ارزیابی‌ها `IN_PROGRESS` باقی ماندند و تأیید نهایی انسانی انجام نشد.

شروع اولیه bootstrap با حساب برنامه به‌دلیل نداشتن اختیار ساخت schema شکست خورد؛ خطای P1010 پیش از تماس ارائه‌دهنده رخ داد. پس از مجوز ادامه، سرور مستقل روی 53306 با datadir موجود و هویت بررسی‌شده اجرا و schema تصادفی تازه ساخته شد. هیچ مجوز یا رمز تولید تغییر نکرد. حساب، عضویت و سازمان مصنوعی غیرفعال، نشست‌ها لغو و فقط سرور مستقل ایجادشده برای آزمون متوقف شد؛ schema برای بررسی حفظ شد. خروجی نهایی، توقف سرور و نبود listener روی 53306 را تأیید می‌کند.

خطاهای اولیه آماده‌سازی نامزد درباره export ساخته‌نشده workspace و typeهای Node در محیط آزمون اصلاح شدند. شکست‌های اولیه حفظ شدند؛ assertion حذف یا آزمونی برای کسب نتیجه موفق، کنار گذاشته نشد.

پیش‌نویس نامرتبط حفظ شد. بررسی عمومی فقط رکوردهای مصنوعی مشخص را به‌روزرسانی کرد؛ ادعای «عدم تغییر هیچ رکورد تولید» برای این مرحله صحیح نیست. وضعیت هر دو ارزیابی DRAFT ماند و تأیید رسمی انجام نشد. ## انتشار، بازیابی و یکپارچگی

انتشار نهایی در زمان و PID جدول مشخصات ثبت شده است. تلاش‌های قبلی برای انتشار، API را موقتاً مختل کردند؛ نسخه قبلی بازگردانده شد. نتیجه ساعت `17:05:31.171Z` با PID برابر 13288، موفقیت کاذب مبتنی بر برچسب نسخه بود: سیستم‌عامل هنوز فایل انتشار قبلی V2 را اجرا می‌کرد. خطای کاربر درباره انتظار V2 هنگام ذخیره رضایت و بررسی مستقل مسیر فرایند، اختلاف را آشکار کرد. این نتیجه در [مدرک اعلام اولیه](evidence/assessment-image-activation-20261022-01/deployment-initial-label-only.json) حفظ شده است.

اصلاح نهایی از `Client.executeRemote('restartProcessId', ...)` با `env.current_conf` و مقادیر صحیح `pm_exec_path`، `script`، `pm_cwd` و `exec_interpreter` استفاده کرد. فقط API restart شد و وضعیت ذخیره‌شده PM2 هم‌راستا شد. مسیر PM2 و command line واقعی سیستم‌عامل برای PID برابر 16632، entrypoint انتشار `release-assessment-image-activation-20261022-01` را تأیید می‌کنند؛ صرف APP_VERSION معیار موفقیت نیست. [مدرک شکست و بازیابی](evidence/assessment-image-activation-20261022-01/deployment-failure.json) نیز حفظ شده و بازگردانی داده پایگاه داده انجام نشده است.

هفت ماژول اجرایی به‌روزرسانی و entrypoint جاوااسکریپت HTML تغییر کرد. CSS عمومی و مکمل موجود، assetهای قدیمی، فایل `.env` خصوصی، schema و نسخه وابستگی‌ها حفظ شدند. مهاجرت اجرا نشد. snapshot خصوصی بازیابی برای همین release نگهداری می‌شود. وضعیت منبع نامزد و تفاوت با checkout جاری در شواهد ثبت است؛ ادعای انتشار کل checkout وجود ندارد.

برای rollback، snapshot معتبر entrypoint و تنظیمات خصوصی فرایند را بازیابی، فقط API را با مسیر اجرایی صحیح restart و سلامت نسخه/پایگاه داده و assetها را بررسی کنید. حذف assetهای قدیمی یا rollback پایگاه داده برای این تغییر لازم نیست. رسیدهای رضایت و نتایج جدید را حذف یا به نسخه قدیمی تبدیل نکنید.

## وضعیت تحویل و محدودیت باقی‌مانده

فعال‌سازی و کنترل‌های فنی در محیط مستقل تأیید و انتشار عمومی با هویت واقعی فرایند ثبت شده است. رضایت V3 با اقدام شخصی کاربر ثبت و در رابط تأیید شد؛ تحلیل تصویری احرازشده هر دو روش، ذخیره نتایج و دریافت PDF عمومی PASS شد. رضایت از طرف کاربر ثبت یا بی‌صدا ارتقا داده نشد. یافته‌های پیش‌نویس همچنان به بازبینی انسانی و تصمیم جداگانه تأیید رسمی نیاز دارند. علت شکست اتصال اولیه و شرایط واقعی ارائه‌دهنده نامعلوم باقی مانده‌اند؛ امنیت کامل مخزن، دقت مستقل آناتومیک یا انطباق حقوقی ادعا نمی‌شود.

## جمع‌بندی مراحل در محدوده اصلاح

وضعیت نهایی ثبت‌شده `PASS_SCOPED_REPAIR` است؛ این وضعیت به اصلاح حاضر محدود است.

| 01 — تحلیل | PASS — علت مسدودشدن تصویر و محدوده حفظ پروژه |
| 02 — UI | PASS — فقط سطح موجود رضایت؛ حفظ UI نامرتبط |
| 03 — فرانت‌اند | PASS — متن و نسخه رضایت؛ 475 آزمون، بررسی نوع و ساخت |
| 04 — بک‌اند | PASS — اصلاح محدود پردازش تصویر؛ بررسی نوع و ساخت |
| 05 — داده | PASS — schema و migration بدون تغییر؛ ذخیره واقعی مستقل و پیش‌نویس‌های آزمون عمومی |
| 06 — یکپارچگی | PASS — 11 بررسی واقعی مستقل و مسیرهای تصویر/PDF عمومی |
| 07 — دسترسی | PASS — رضایت جاری، نقش، سازمان، صاحب تصویر، سهمیه و مجوز پیش از ارسال |
| 08 — امنیت | PASS — بازبینی مستقل محدوده مرز اعتماد؛ بدون یافته مادی معرفی‌شده حل‌نشده |
