## جمع‌بندی

خطای HTTP 401 قبلی با تنظیم فعلی به‌طور قطعی بازتولید نشد: اعتبارنامهٔ نگهداری‌شده در فایل محافظت‌شدهٔ سرور یک بار برای فهرست مدل‌ها و یک بار برای تحلیل متنی GPT-5-Mini پذیرفته شد، اما درخواست فهرست مدل بعدی با همان منبع پیکربندی HTTP 401 گرفت. بنابراین هنوز نمی‌توان مشخص کرد رد شدن به‌علت وضعیت/دسترسی اعتبارنامه است یا رفتار ناپایدار درگاه. درخواست تصویر مصنوعی به لایهٔ تحلیل مدل رسید، ولی پاسخ با قالب مورد انتظار RULA تطبیق نکرد. هیچ نتیجه‌ای ذخیره نشد.

## آنچه بررسی شد

1. سرویس جاری API با PM2 اجرا می‌شود و از فایل نسخهٔ منتشرشدهٔ ۱۵ اکتبر استفاده می‌کند؛ سلامت محلی API در این بررسی HTTP 200 بود.
2. ارائه‌دهندهٔ تنظیم‌شده ArvanCloud و نشانی پایه `https://api.arvancloudai.ir/v1` است. اعتبارنامه در گزارش یا خروجی ابزار نمایش داده نشد.
3. فراخوانی متنی GPT-5-Mini با پاسخ HTTP 200 و متن مورد انتظار موفق شد. مدل‌های GPT-5-Mini، GPT-4.1-Mini، GPT-4o-mini و DeepSeek-V4-Flash در پاسخ کاتالوگ موفق فهرست شده بودند.
4. یک تصویر مصنوعی و غیرشخصی با مدل تصویری اصلی نسخهٔ جاری اجرا شد. پاسخ به تجزیه‌گر محلی رسید، اما ساختار RULA معتبر نبود؛ نتیجهٔ دستی/تأییدشده‌ای ایجاد نشد.
5. دروازه‌های مجوز حریم خصوصی و تأیید قابلیت تصویر برای اجرای API خالی هستند و همچنان بسته مانده‌اند.

## موارد حل‌نشده

- خطای 401 تاریخی درخواست آزمایشی با شناسهٔ پالایش‌شدهٔ `b8e12c19-f17b-4c7a-9cdd-875209157873` هنوز علت قطعی ندارد؛ گزارش قبلی وضعیت HTTP 401 ارائه‌دهنده و خطای امن 503 برنامه را ثبت کرده بود.
- کد اجراشدهٔ RULA در نسخهٔ منتشرشده از GPT-4.1-Mini و سپس GPT-4o-mini استفاده می‌کند؛ کد منبع فعلی GPT-5-Mini را برای تصویر انتخاب می‌کند. این اختلاف باعث می‌شود بررسی منبع به‌تنهایی رفتار سایت را نشان ندهد.
- آزمون احراز‌شدهٔ کاربر عادی تا ذخیره، بازگشایی و گزارش در پایگاه آزمایشی انجام نشد؛ پیکربندی و اعتبارنامهٔ جداگانهٔ staging در دسترس نبود. به پایگاه دادهٔ فعال اتصال نوشتنی انجام نشد.

## اقدام لازم

مسئول حساب ArvanCloud باید از پنل یا پشتیبانی ارائه‌دهنده، فعال بودن کلید و مجوز آن برای endpointهای `/v1/models` و `/v1/chat/completions` و مدل تصویری موردنظر را بررسی کند و علت رد شدن درخواست 401 را با شناسهٔ درخواست از ارائه‌دهنده دریافت کند. کلید را در گفت‌وگو ارسال نکنید. پس از تأیید جداگانهٔ پردازش تصویر و فراهم شدن محیط آزمایشی جدا، آزمون API احراز‌شده و ذخیره/بازگشایی RULA قابل اجراست.

## انتشار

در این بررسی کد برنامه، تنظیمات زنده، سرویس، پایگاه داده و حساب‌ها تغییر نکردند؛ انتشار یا راه‌اندازی مجدد انجام نشد. تنها اسکریپت تشخیصی محلی اصلاح شد تا فایل محیط محافظت‌شده را بخواند و در نبود کلید درخواست نسازد. نتیجهٔ اجرای اصلاح‌شده همچنان HTTP 401 بود.
