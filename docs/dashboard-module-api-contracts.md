# NIVASafe dashboard module API contracts — Task 05

Date: 2026-10-15. These contracts describe the current source implementation and focused Fastify tests. The new migration has not been applied to a database, so none of these routes have been verified against a live MySQL service.

## Shared behavior

- Routes are mounted under `/api/v1` by the existing Fastify app and use the existing JWT/session authentication, current organization header/session selection, Zod validation, and `{ data, meta? }` response envelope.
- List endpoints use page/limit metadata and enforce the current organization in the Prisma `where` clause. Missing or inaccessible IDs return `404` to avoid cross-organization existence disclosure. Input and state-transition errors return 4xx through the existing error handler.
- Audit entries record workflow metadata and identifiers. Incident descriptions, checklist answers, and support reply bodies are not copied into audit metadata.
- New records are saved in the backend. Browser state is only used for unsaved form input; reload reads records back from the authenticated API.

## Checklists and audits

Frontend: `/checklists` (`frontend/src/features/checklists/ChecklistsPage.tsx`). The route and sidebar allow the current inspector roles: `SUPER_ADMIN`, `ORG_ADMIN`, `HSE_MANAGER`, `HSE_SPECIALIST`, `HSE_OFFICER`, `EXTERNAL_AUDITOR`, and `ASSESSOR`. Managers are `SUPER_ADMIN`, `ORG_ADMIN`, and `HSE_MANAGER`. The server applies the same role gates; UI visibility does not grant access.

### Templates

| Method and route | Request / query | Permission and behavior |
|---|---|---|
| `GET /checklists/templates` | `page`, `limit` (max 100), `search`, optional `status` (`DRAFT`, `PUBLISHED`, `SUPERSEDED`) | Authenticated org member. Managers can list requested statuses; other inspectors see only `PUBLISHED`. |
| `POST /checklists/templates` | `{ title, description?, items: [{ label, required? }] }`; 1–100 items | Manager only. Creates version 1 as `DRAFT`; item IDs are generated by the server. |
| `POST /checklists/templates/:id/versions` | A non-empty partial `{ title?, description?, items? }` | Manager only. Source must be a published template in the current org. Creates the next draft version; items receive new IDs. |
| `PATCH /checklists/templates/:id` | A non-empty partial `{ title?, description?, items? }` | Manager only. Updates the latest organization-owned `DRAFT`; published/superseded or stale versions return `409`. |
| `POST /checklists/templates/:id/publish` | `{}` | Manager only. Publishes the latest draft and marks the former published version `SUPERSEDED` in one Prisma transaction. |

`title` is trimmed and 3–191 characters. `description` is optional/nullable and up to 4,000 characters. Each trimmed item label is 2–191 characters; `required` defaults to `true`. Publication does not convert findings into actions.

### Inspections

| Method and route | Request / query | Permission and behavior |
|---|---|---|
| `GET /checklists/inspections` | `page`, `limit` (max 100), optional `status` (`IN_PROGRESS`, `SUBMITTED`, `APPROVED`, `NEEDS_REVISION`) | Inspector only. Managers see the organization queue; other inspectors see inspections assigned to them or started by them. |
| `POST /checklists/inspections` | `{ templateId, projectId?, assignedToId? }` | Inspector only. Template must be published and organization-owned; optional project must belong to the same org. Default assignee is the current user. Assigning another active org member is manager-only. |
| `GET /checklists/inspections/:id` | — | Inspector only. Same manager-vs-assigned/started scope as the list. |
| `PATCH /checklists/inspections/:id` | `{ answers: [{ itemId, result: "PASS" | "FAIL" | "NOT_APPLICABLE", note? }] }` | Assigned inspector or manager; only `IN_PROGRESS` and `NEEDS_REVISION`. Item IDs must belong to the frozen snapshot; duplicate/unknown items are rejected. `FAIL` requires a non-empty note. |
| `POST /checklists/inspections/:id/submit` | `{}` | Assigned inspector or manager; required questions must have answers; state becomes `SUBMITTED`. |
| `POST /checklists/inspections/:id/review` | `{ decision: "APPROVED" | "NEEDS_REVISION", note? }` | Manager only; only submitted inspections can be reviewed. Reviewer and timestamps are recorded. |

The persisted inspection stores a snapshot of template version/items and JSON answers. This slice does not implement attachments, evidence, due-date scheduling, project selection, assignment editing, or a corrective-action reference. A failed item remains a checklist finding until a separate, explicit action workflow is implemented.

## Incident and near-miss intake

Frontend: `/incidents` (`frontend/src/features/incidents/IncidentsPage.tsx`). All authenticated organization members can submit reports and read their own records. `SUPER_ADMIN`, `ORG_ADMIN`, and `HSE_MANAGER` can list all reports in the current organization and update review status.

| Method and route | Request / query | Permission and behavior |
|---|---|---|
| `GET /incidents` | `page`, `limit` (max 100), optional `status` (`REPORTED`, `UNDER_REVIEW`, `CLOSED`) | Organization-scoped. Non-managers are additionally limited to `reporterId = current user`. |
| `POST /incidents` | `{ kind: "INCIDENT" | "NEAR_MISS", occurredAt, projectId?, location, summary, description }` | Authenticated org member. `occurredAt` must be ISO datetime with timezone; project, when supplied, must be an active project in the same org. Starts in `REPORTED`. |
| `GET /incidents/:id` | — | Reporter or manager in the current organization. Others receive `404`. |
| `PATCH /incidents/:id` | `{ status: "REPORTED" | "UNDER_REVIEW" | "CLOSED" }` | Manager only. Legal transitions: `REPORTED → UNDER_REVIEW/CLOSED`, `UNDER_REVIEW → REPORTED/CLOSED`, `CLOSED → UNDER_REVIEW`. Invalid transitions return `409`. |

Location and summary are 2–191 and 3–191 characters respectively; description is 10–10,000 characters. Audit metadata contains the report kind or new status, not personal/event narrative. There is no severity or risk scoring, classification policy, investigation, witness/evidence, action linking, or approval-history module in this slice. Users must not interpret report status as an investigation or safety determination.

## Support request conversation

The existing `SupportRequest` remains the canonical token/plan/technical request. Requesters remain tenant- and owner-scoped. The global support queue is still restricted to `SUPER_ADMIN`; no new support-agent role or broader organization visibility is introduced. Reply bodies are append-only `SupportReply` records. `idempotency-key` must be a UUID and is unique for organization, request, author, and key.

| Method and route | Request / query | Permission and behavior |
|---|---|---|
| `POST /support/requests` | `{ category, subject, message }`, `idempotency-key` header | Existing authenticated requester flow; rate limited. Plan or AI-quota request is not an entitlement change. |
| `GET /support/requests` | `page`, `limit` (max 100), optional status | Current requester and current org only. |
| `GET /support/requests/:id` | — | Current requester and current org only; includes replies oldest-first and limited author fields. |
| `POST /support/requests/:id/replies` | `{ message }`, `idempotency-key` header | Requester-owned ticket only; 1–4,000 trimmed characters; rate limited. A requester reply reopens `RESOLVED` or `CLOSED` to `OPEN`. |
| `GET /admin/support-requests` | `page`, `limit`, optional status | Global `SUPER_ADMIN` only; existing admin inbox. |
| `GET /admin/support-requests/:id` | — | Global `SUPER_ADMIN` only; includes request, org/requester summary, and replies. |
| `POST /admin/support-requests/:id/replies` | `{ message }`, `idempotency-key` header | Global `SUPER_ADMIN` only; appends reply, audits safe metadata, and notifies the requester in their locale. |
| `PATCH /admin/support-requests/:id` | Existing `{ status?, response? }` legacy review shape | Global `SUPER_ADMIN` only. Changed non-empty legacy response is also appended to `SupportReply` and notifies the requester. The old response field remains for compatibility. |

An idempotency retry with the same key and same body returns the existing reply; reuse with a different body returns `409`. The admin inbox detail and requester detail enforce their existing role/owner boundaries. Attachments, priority, SLA, and a separate support-agent role are not implemented.

## Routes intentionally left pending

Chemical scoring, work permits, questionnaires, managed plans/maps, workplace measurements and exposure guidance, occupational health surveillance, and industrial ventilation remain pending in navigation. Their policy or domain data is absent; this task does not invent safety scores, legal thresholds, clinical data, or engineering conclusions. Existing `/health` continues to mean technical system health.
