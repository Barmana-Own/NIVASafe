# PWA and offline

The web app ships a complete installable PWA: manifest metadata for desktop and mobile, a PNG maskable icon, install shortcuts, an offline fallback and an in-app install prompt backed by the browser's native `beforeinstallprompt` flow. On iOS, the prompt explains the Share → Add to Home Screen path because Safari does not expose that event. The prompt is dismissible and does not interrupt standalone installations.

The service worker uses a network-first strategy for navigations and a cache-first/stale-refresh strategy for static assets. API responses, credentials and uploaded files are never cached; navigation cache keys drop query strings so transient URL parameters are not retained. Shell precaching is best-effort so one unavailable optional asset cannot block worker installation, and network requests have an eight-second timeout before the offline fallback is used. New service-worker versions normally remain waiting until the user chooses «به‌روزرسانی»; the page reloads once after activation so users never see a mixed asset version. Release `v12` is a one-time emergency migration: it skips the waiting phase, claims existing windows and navigates them once so clients controlled by a stale cached shell leave the previous production bundle. Subsequent releases return to the normal user-controlled update flow. Registration disables the browser's service-worker HTTP cache, checks for updates on registration, visibility, page show and reconnection, and performs a bounded periodic check while the app is open. A dismissed banner remains hidden for the same waiting worker but reappears for a newer release. Production Nginx serves `sw.js` and the manifest with revalidation headers so installed clients discover updates promptly. Increment `VERSION` in `frontend/public/sw.js` for each release that changes the application shell or cache contract; the current deployed worker is `v12`.

FMEA and RULA form drafts are written synchronously to user- and organization-scoped localStorage and backed up to serialized IndexedDB writes; this preserves the latest entered values across refreshes, power loss and temporary offline periods. The full draft is restored on return, can be synchronized after reconnection, and is deleted from both stores only after successful submission. Logout clears browser caches. The manifest includes `scope`, `id`, standalone display mode and shortcuts for Dashboard, FMEA and the assistant, so desktop and mobile installations open directly in the app shell.
