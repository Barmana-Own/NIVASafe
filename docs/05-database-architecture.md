# Stage 05 — Database Architecture

Migration `202609050001_fmea_process_information` adds `JobCatalog` and nullable process fields to `FmeaAssessment`. `JobCatalog` supports active global records (`organizationId = NULL`) and organization-owned records, with indexes for organization/active state and localized titles. The FMEA foreign key uses `ON DELETE SET NULL`; existing assessments therefore remain readable if a catalog record is retired.

The migration seeds four global starter jobs and the development seed reproduces them idempotently. Equipment, materials and controls are JSON arrays because they are bounded, user-confirmed lists attached to one assessment. Migration `202609050002_fmea_report_actions` adds the nullable `CorrectiveAction.fmeaItemId` link and index, with `ON DELETE SET NULL`, so report action history remains intact if a risk row is removed. Migration `202609050003_rula_process_information` adds nullable `RulaAssessment.activityInfo` JSON for validated job/task measurements, posture duration, load units and the future posture-image reference. Migration `202609050004_rula_posture_analysis` adds nullable `RulaAssessment.postureAnalysis` JSON for editable Group A/Group B observations, provenance, angle values and detection state. Migration `202609060001_rula_corrective_action_impact` adds nullable `CorrectiveAction.rulaImpact` JSON for the suggestion identifier, bounded estimated score reduction and affected posture parts. Migration `202609090001_ai_usage` adds the additive `AIUsageRecord` table with source idempotency, user/organization indexes and restrictive accounting-history foreign keys. Migration `202609190001_fmea_risk_bands` adds `VERY_LOW` to the FMEA enum, changes default organization thresholds to 101/201/401 and reclassifies existing rows using the reference boundaries. It was applied on production with the supported MariaDB client and recorded in `_prisma_migrations`; the rollback database dump is retained. The local database already existed, so clean migration deployment remains `NOT_RUN`; Prisma validation, client generation and the production migration verification passed. The manual MySQL schema export was updated.
