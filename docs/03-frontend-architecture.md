# Stage 03 — Frontend Architecture

The public login mobile shell keeps breathing room around the toolbar contents, uses the smart occupational safety and health brand subtitle in both locales, and anchors the support/approval bar to the bottom edge while preserving the device safe-area inset.

The authenticated shell keeps the topbar title and utility controls on one row from the wide desktop range through the 761–1280px tablet range, and preserves the compact mobile row below 760px. Shared PageHeader actions use compact 0.78rem typography from 761px through 1280px so dashboard and FMEA/RULA controls remain readable without breaking their labels. The RTL language menu is anchored to the viewport-safe inline edge on narrow screens, preventing it from being clipped outside the page. The assistant route uses a bounded two-row mobile layout: the conversation list remains scrollable, the chat log keeps the remaining viewport height, and the composer retains touch-sized controls so a conversation can be started or continued without horizontal overflow.

The authenticated `/activity-log` surface is available to every signed-in user. Ordinary users receive their own sign-in/sign-out, assessment and AI activity; organization administrators and HSE managers receive the selected organization's activity, including active covered members. The table resolves FMEA/RULA titles and codes and shows provider-reported AI token totals when a matching usage record exists. The legacy `/audit` route remains a redirect for compatibility.

`DashboardPage` keeps the existing dashboard data and widget rendering path while adding a local, user-and-organization-scoped layout model. The layout editor supports drag-and-drop and keyboard ordering, explicit show/hide controls, reversible removal/restoration and a reset-to-default action; a reachable empty state is rendered when no widget remains visible. `AppLayout` keeps route permissions intact, organizes the navigation into product-area groups, exposes accessible collapse/expand state, preserves labels for collapsed links and matches nested routes for the top-bar title. Responsive shell rules preserve the existing mobile drawer and add a usable expanded tablet state.

`AppLayout` also owns the authenticated theme preference. `ThemeSwitcher` exposes exactly two localized choices (`blue` and `white`) with `aria-pressed` state; `theme.ts` validates and persists the preference safely in localStorage, defaulting to blue/dark when storage is unavailable or malformed. Theme-specific shell CSS changes the sidebar/topbar treatment and switches the sidebar mark to white in blue/dark mode or the original blue asset in white/light mode without changing route or data behavior.

`PathSelectionPage` remains on the existing authenticated `/choose-path` route and owns only assessment-method selection. It reads the session path key with a local-storage fallback for a sensible default, writes the confirmed FMEA/RULA path to the active session before navigation, and renders semantic, keyboard-accessible cards with direct entry buttons, double-click continuation compatibility and a responsive mobile layout. Starting a new assessment from this surface clears only the selected method's user/organization-scoped localStorage and IndexedDB draft plus its wizard-step marker before navigation, so all form controls start empty; leaving an active assessment without making that fresh-selection action continues to use autosave for recovery. FMEA and RULA headers expose the existing route-safe change-method link back to `/choose-path`.

FMEA is split by responsibility under `frontend/src/features/assessments/fmea/`. `FmeaFeature.tsx` owns the process-information, review/register, risk-register and route-level report orchestration while `FmeaReportComponents.tsx` owns the report summary, distribution chart, score guide, report table and export context. RULA is isolated under `frontend/src/features/assessments/rula/RulaFeature.tsx`, which owns the posture-analysis workflow, side-aware score review, report route and corrective-action state. `AssessmentPages.tsx` is a compatibility barrel that re-exports both assessment route families, so existing App route imports remain stable while neither assessment implementation is kept in the barrel. Shared assessment types, draft helpers, catalog search and image/detail overlays live in `assessmentShared.tsx`. The reusable `JobCatalogSearch` and `ProcessSuggestionPicker` isolate catalog search and confirmation behavior without duplicating page logic; the bounded description assistant writes a validated response directly into the activity-description textarea and returns focus to that field. FMEA creation uses two pre-submit states (process information, then review/register) while the existing `/fmea/:id/report` route is the third report/results stage. The current pre-submit state is scoped to the draft key in `sessionStorage`, successful POST navigation uses the returned assessment ID, and registration is guarded so repeated clicks cannot create duplicates. The FMEA stepper now exposes direct buttons for process information and review/register without running validation during navigation; the report-stage button is enabled when an existing assessment has a report route and returns authorized editors to the requested edit stage. The RULA three-stage stepper uses the same direct-navigation behavior, while final registration still validates process information and unconfirmed posture results.

The page uses the centralized `api` transport, `useLoad` for projects/assessments, the existing i18n dictionaries, and the existing localStorage/IndexedDB draft helpers. Request IDs prevent stale catalog or AI responses from overwriting a newer job selection. Form snapshots contain only safe operational fields; password and file exclusions remain enforced by the shared autosave layer.

The selected assessment renders a complete FMEA risk register with search, risk-level filtering, numeric sorting, an S/O/D scoring guide, detail inspection, inline row editing and permission-gated actions. New risk-row entry intentionally omits manual row-number and process-stage controls; the backend derives those legacy fields while the existing edit and display paths remain compatible. Panel export actions expose structured Excel (`.xlsx`) and real Word (`.docx`) output from the same register; the PDF compatibility endpoint is not rendered as a panel control. `FmeaReportPage` is a separate route-level surface that consumes the typed report read model, renders summary/top-risk/action/detail states, and creates tenant-validated corrective actions through the central API client. Binary downloads keep their object URLs alive until the browser has consumed the download and then clean them up. The FMEA risk-row suggestion assist keeps at most six suggestions per category, renders three initially and exposes an independent accessible plus/minus toggle for the remainder while preserving explicit acceptance. The same AI response now carries a bounded advisory S/O/D score suggestion; it is rendered after the score panel with an explicit apply/dismiss action, and applying it updates controlled selectors so RPN recalculates without refresh. The reusable score-panel fields and actions keep selectors, RPN preview, calculated five-level risk badge and submit/save controls aligned on desktop and stack responsively; selector labels and criteria are mapped to the supplied FMEA reference scale in both locales.

Client validation is supplemental: the backend remains authoritative. The production build, typecheck and frontend tests pass.

The Vite configuration derives `process.env.NODE_ENV` from the build mode and defines the same value for the emitted bundle. This prevents a repository development `.env` from causing a production build to include React development diagnostics such as the DevTools console notice, while preserving the development runtime for `vite` dev sessions.

## Responsive foundation and navigation loading

The shared stylesheet now follows the documented 320–479, 480–767, 768–1023, 1024–1279 and 1280+ responsive contract. Shell containers, page headers, surfaces and form/grid boundaries are explicitly shrink-safe, while page action controls use an auto-fitting mobile grid with readable wrapping instead of contradictory two-column/one-column overrides or forced `nowrap` labels. The global document shell no longer masks horizontal overflow with `overflow-x: hidden`/`clip`; dense tables retain scrolling only inside their explicit `.table-wrap` containers and component-level mobile card rules own their overflow.

The public login shell uses natural document flow with `min-height: 100dvh` and scrollable page behavior. The mobile form no longer depends on a fixed `max-height` that can trap content when the virtual keyboard reduces the viewport. Authenticated sidebar drawer behavior and the bounded assistant workspace remain intentionally scoped.

`ApplicationRoutes` no longer renders the former timer-based `RouteTransitionLoader`. Navigation is not delayed by an unconditional 420ms timeout; real page and API loading states continue to be owned by their respective screens and data hooks.

The registration flow always opens on the personal/organization account-type selector, even when a recoverable draft exists. Draft kinds are normalized before use, the selector is exposed as an accessible radio group, and later steps retain an explicit change-type action without discarding saved fields. Login submits credentials and, after the authenticated response is validated, persists the first server-assigned organization membership before navigating directly to the panel. The existing in-panel company switcher remains the place to change among authorized workspaces; no intermediate role/workspace chooser is rendered.

The registration wizard retains its existing component and route structure. Its personal path validates name parts, contact type and credentials before review; its organization path separates responsible-person and company/account steps, validates company fields and national-ID checksum, repeats all captured values in the review summary, and renders a success destination after the existing register-then-login sequence. Draft persistence excludes both password fields, and duplicate submits are blocked while the request is in flight.

`OrganizationsPage` is the multi-company workspace surface. It keeps current-company editing and billing controls role-gated, while allowing any authenticated user to submit a new company request. Creation disables duplicate submissions, merges the server-returned membership into the session and selects that company through `selectOrganization`; the helper rejects locally forged or stale organization IDs before navigation. The top-bar selector and company-list entry use the same membership-checked helper, so switching is consistent across desktop and mobile shell layouts.

`ProjectsPage` keeps the existing tenant-scoped project list and counts, but consolidates project/process/activity setup into the single project-creation card. The card captures the project fields plus an initial process name, initial activity title and optional activity location; separate process/activity forms and process/activity list cards are no longer rendered on this page. The centralized API submission remains autosaved and disables duplicate clicks, then refreshes the existing project and count read models after the server transaction succeeds.

`PwaManager` owns the browser install lifecycle without coupling it to assessment or authentication state. It stores the deferred `beforeinstallprompt` event for desktop/Android, provides an iOS Add to Home Screen hint, detects standalone mode, handles dismissal without repeated interruption, and cleans up media-query, service-worker and window listeners. The manager checks for a new worker on registration, page show, visibility and reconnection plus a bounded interval; a waiting worker is activated only after the user selects update, then the controlled page reloads once with a timeout fallback.

## Responsive table implementation

All application tables now use the shared `TableContainer` boundary. FMEA risk/register/report/action tables, score guides, RULA analysis/report/correction tables, Actions, Activity Log, AI token usage and administrator user/member tables provide `data-label` values for their cells. Desktop keeps semantic tables, tablet uses bounded container scrolling for dense column sets, and phones use wrapped two-column cards with full-width narrative and operation fields. RULA's existing posture/report card treatment remains the domain-specific presentation inside the shared container rather than being replaced by a second data model. Row state, filtering, editing, status updates, permission checks and exports remain in their existing feature components.

## Authenticated shell responsive behavior

`AppLayout` keeps the mobile topbar focused on navigation, the current route and notifications. Theme, locale and subscription controls remain available in a dedicated mobile drawer utility area, so secondary controls do not compress or widen a 320px viewport. The drawer has a bounded width, a vertically scrollable navigation region, a backdrop, safe-area padding and explicit close behavior for Escape, backdrop clicks and route navigation. Opening the drawer locks the document scroll without losing the scrollbar position; focus enters the drawer and returns to the menu trigger when it closes.

The desktop expanded/collapsed sidebar preference remains persisted under `nivasafe-sidebar-collapsed`. Tablet widths keep the preference-driven expanded or collapsed layout, while the phone breakpoint switches to the off-canvas drawer. The route title is visually ellipsized only when necessary and keeps the full localized value through `title` and `aria-label`. `IconButton` now forwards its button ref so shell focus management remains semantic and reusable.

## Overlay and file-preview implementation

`frontend/src/components/Overlay.tsx` provides the shared portal root, viewport-safe floating-position calculation, body-scroll lock and focusable-element discovery. The custom select and localized date picker preserve their hidden/native form controls while portaling their visible menus/calendars; language and theme menus use the same boundary. The shared dialog provider now uses a portal, focus trap, Escape handling, focus restoration, safe-area sizing and serialized promise settlement so replacing an open prompt cannot orphan its resolver.

Supported image, video and PDF file previews are rendered in an in-app `Modal` from `FilesPage`. Preview object URLs are replaced and revoked on close, replacement, stale-request cancellation and unmount. Unsupported formats remain downloadable through the modal fallback. No parent surface or table is made `overflow: visible` to host an overlay.

## Accessibility implementation

The frontend applies the shared touch target to legacy icon and compact action controls, adds contextual labels to attachment, notification, widget, assessment and row operations, and uses semantic buttons for previously keyboard-only card/image interactions. The app shell includes a localized skip-to-content link and focusable main landmark; mobile drawer focus trapping and document-root scroll locking remain active. Password reveal controls expose `aria-controls` and `aria-pressed`, asynchronous errors/success states use appropriate live-region semantics, and focused UI tests cover labels, semantic cards, focus-visible rules, reduced motion and chart/status accessibility.

## Final stylesheet organization

The application imports `frontend/src/styles.css` from `main.tsx`; that file is a compatibility entry point containing only `@import "./styles/index.css"`. `styles/index.css` defines the complete and reviewable cascade order. Shared foundations are separated into `tokens.css`, `base.css`, `layout.css`, `buttons.css`, `forms.css`, `tables.css`, `overlays.css`, `themes.css`, `responsive-shell.css`, `responsive.css` and `print.css`. `responsive.css` owns the final generic page-action contract, while `responsive-shell.css` remains limited to shell behavior. Feature-specific presentation is grouped under `styles/features/` for FMEA and RULA, while admin, account, files, assistant and path surfaces retain focused top-level modules where their selectors are not shared primitives.

This organization preserves selector compatibility while making ownership explicit. Responsive rules use the established content breakpoints, `min-width: 0`/`minmax(0, 1fr)` shrink contracts and bounded data scrollers. The stylesheet no longer relies on global horizontal clipping, table-wide `white-space: nowrap`, or overflow-visible ancestors for floating controls; overlays are portalized. Source contract tests protect the durable architecture, and Playwright visual/overflow tests remain the authority for rendered layout.
