## Task 06 implementation outcome

- RULA image cards now distinguish queued, analyzing, ready, failed, and cancelled states. A failed image exposes a per-image retry when the existing error is retryable, an error explanation, and a contextual link to the existing support page. Retryable errors are limited to the API's existing provider/network/408/5xx cases; permission, subscription, quota, and other non-retryable failures are not retried.
- Manual continuation is explicit after an image fails or is cancelled. Every failed image must have user-confirmed entries for all seven RULA anatomical parts before the wizard can advance. `BOTH` requires both sides. Failed photos enter the report only after that review, remain marked as manually reviewed, and do not receive AI model provenance. The RULA calculation and save payload remain on the existing path.
- The active photo review is saved before either wizard path validates the report step, and partial manual edits are restored when switching back to a failed photo.
- When the current API returns a numeric confidence, the posture table displays that value as a percentage. No confidence-based review threshold was introduced. Existing overlay handling and calculations remain intact.
- RULA validation errors and wizard-step changes receive keyboard focus; status text remains announced through the existing status regions. Both language bundles were updated for new recovery and support copy.
- The canonical `/support` page now has server-backed status/page navigation using the existing pagination metadata, explicitly page-scoped search and category filtering, safe editable RULA context, direct ticket deep links, and visible ticket references/update dates/thread replies. The existing super-admin inbox now pages using its existing API. Category/search filters stay local because the API accepts no such query fields.
- No backend route, schema, migration, permission, quota, notification contract, AI provider, RULA calculation, or deployment file changed. Attachment upload, server-wide search, unread/reply counts in list responses, priority, assignment, internal notes, activity history, ticket-specific notification links, and distinct image-quality errors remain Task 07 API work.
- Automated checks passed when run with the repository-documented local Unicode font paths for PDF tests. Browser verification of protected RULA/support pages is blocked because the local browser had no authenticated account and no API/database service. Windows rendering was not available. Exact command results are recorded in `task-06-ui-verification.md`.

Backend-only work remains assigned to Task 07; no quota, authorization, AI inference, persistence, or migration behavior was changed by this frontend task.
