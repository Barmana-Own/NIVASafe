# Stage 06 — API Design and Integration

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/v1/fmea/job-catalog?search&limit` | Return active global and current-organization job entries; `limit` is bounded to 200 for the initial client-side catalog load. |
| POST | `/api/v1/fmea/process-suggestions` | With `mode=suggestions`, return catalog/AI process-item suggestions; with `mode=description`, return a bounded description suggestion; with `mode=risk-row`, return bounded failure-mode/effect/cause/recommendation suggestions plus an advisory integer S/O/D score suggestion and rationale; with `mode=job-titles`, preserve the bounded organization-scoped compatibility flow for explicit callers. The live title combobox uses `GET /fmea/job-catalog` and does not invoke this mode. Confirmed assessment fields are not written by suggestion modes. |
| POST | `/api/v1/fmea` | Persist the user's confirmed process information and assessment metadata. |
| GET/PATCH | `/api/v1/fmea/:id` | Read or update an assessment while preserving tenant and catalog checks. |
| POST/PATCH/DELETE | `/api/v1/fmea/:id/items[/:itemId]` | Create, edit or delete a risk row; on create, legacy `rowNumber` and `processStep` are optional and are derived from the parent assessment when omitted; the server recalculates RPN and risk level using VERY_LOW 1–50, LOW 51–100, MEDIUM 101–200, HIGH 201–400 and CRITICAL above 400. |
| GET | `/api/v1/fmea/:id/report` | Return the tenant-scoped FMEA header, executive summary, risk distribution, top failure modes, suggestions, action register and complete detail rows. |
| POST | `/api/v1/fmea/:id/report/save` | Record an audit-backed report-save event for the current assessment version. |
| GET | `/api/v1/actions?fmeaId=...` | Filter corrective actions by FMEA assessment. Actions may link to a specific `fmeaItemId`. |
| POST/PATCH | `/api/v1/actions[/:id]` | Create or update a corrective action with tenant-validated project/FMEA/FMEA-row links. |
| GET | `/api/v1/reports/{fmea,rula}/:id.{pdf,xlsx,doc,docx}` | Export the selected FMEA or RULA report. `xlsx` is a structured Excel workbook; `docx` is a real Office Open XML Word document. `doc` remains a backward-compatible alias for DOCX. |
| POST/PATCH | `/api/v1/rula[/:id]` | Create or update a RULA assessment with validated activity information, editable Group A/B posture analysis, measurement units, load context and scoring inputs. |
| GET | `/api/v1/rula/:id/report` | Return the tenant-scoped RULA result read model: score/risk, main factors, suggested corrective actions, persisted actions and predicted score. |
| POST/PATCH/DELETE | `/api/v1/actions[/:id]` | Create, update or remove corrective actions; RULA actions may carry bounded `rulaImpact` metadata linked to a RULA assessment. |
| POST | `/api/v1/files` with `entityType=RulaAssessment` | Upload an authenticated posture image for an existing RULA assessment; the server validates tenant ownership, image signature and the 10 MB limit. |
| GET | `/api/v1/admin/ai-usage?page&limit&search` | Return provider-reported AI token aggregates per user; `SUPER_ADMIN` sees all users and `ORG_ADMIN` sees only the selected organization. |
| POST | `/api/v1/auth/login` | Verify credentials and return the authenticated user with active organization memberships; the frontend persists the first returned organization for initial scope, but never submits a role assignment. |
| GET/POST | `/api/v1/organizations` | List memberships visible to the authenticated account or create a new organization with an `ORG_ADMIN` membership and localized `DEFAULT` project; creation returns the independent subscription state. |
| POST | `/api/v1/projects` | Create a project with an optional initial process/activity bootstrap; the process name and activity title are validated as a pair, and the optional location is persisted on the linked activity in the same transaction. |
| GET/PATCH | `/api/v1/organizations/current` | Read or edit the selected organization identified by the server-validated `x-organization-id` header. |
| GET/POST | `/api/v1/organizations/current/subscription[/checkout]` | Read or activate the selected organization's independent subscription; production checkout requires an external payment adapter, while local simulation is development-only. |
| POST | `/api/v1/auth/register` | Accept the existing personal or organization registration contract; server-side validation normalizes contacts, validates name parts and organization identifiers, creates the user/workspace/membership/default project atomically, and never returns internal validation details to the UI. |

All responses use the existing `{ data: ... }` envelope. Search and item counts are bounded. Suggestion endpoints never write confirmed FMEA process fields; only the create/update endpoints persist values included by the client and validated by the API. The `job-titles` mode is the exception for the job bank: it writes bounded organization-scoped AI title records to `JobCatalog` with duplicate checks and returns those records for inline selection, without linking them to an assessment. Project creation can atomically persist the initial process and linked activity while remaining backward-compatible for callers that omit the bootstrap fields. Custom job titles remain assessment-local (`jobCatalogId=null`) until the user selects an existing catalog entry. Frontend contract verification reports all current frontend paths matched backend routes.

Risk-row mutations require tenant-scoped assessment permissions and item deletion is confirmed in the UI. Risk-row AI score suggestions are constrained to integer values from 1 through 10, parsed server-side, returned as advisory data only and never persisted by the suggestion route. The report and action routes use the same tenant and permission boundaries. Word exports are generated as valid Office Open XML packages with the `application/vnd.openxmlformats-officedocument.wordprocessingml.document` content type; the legacy `.doc` URL is accepted for compatibility and returns the same `.docx` package. Excel exports are generated as valid `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` workbooks with separate summary, process/factor and action sheets where applicable.

RULA `activityInfo` and `postureAnalysis` are stored separately from the scoring `inputs` JSON and are validated at the API boundary. The activity context includes an optional bounded `postureDescription` for the assessor's notes. Posture images are uploaded after the assessment is created, then linked through the tenant-scoped attachment record; cross-assessment or cross-organization image references are rejected. The API recalculates score/action level from the submitted scoring inputs, so client-side edits cannot make the stored result authoritative without server validation. The report endpoint derives the main factors and bounded suggestions from the persisted posture observations. A corrective action stores only a bounded reduction estimate and affected posture parts; the report sums selected reductions with a score floor/ceiling and labels the result as a prediction.

AI usage is recorded after successful provider calls for risk requests and chat responses. The aggregate endpoint returns counts only, uses bounded pagination/search, and excludes prompt, completion, credential and raw-provider data.

Organization creation is intentionally available with `allowUnsubscribed` so a user can reach the payment surface for a newly provisioned company. The created organization is `TRIALING` only in development; production creation is `PENDING_PAYMENT`, and the normal authenticated route guard blocks all tenant operations that do not explicitly belong to billing or recovery.

The registration UI keeps the existing wizard and adds a visible personal/organization path, organization manager/company/review steps, recoverable non-secret draft fields, field-local validation, and an explicit success destination. The organization account email is the responsible user's validated login email in the current data model; the review step repeats all captured company and manager fields before submission.
