# Stage 01 — Traceable Requirements

| ID | Requirement | Acceptance evidence |
|---|---|---|
| FR-FMEA-PROC-001 | The FMEA process step captures job/process, department, activity description, equipment, materials, controls and special conditions. | Form payload and Prisma fields |
| FR-FMEA-PROC-002 | Job/process search returns matching active catalog entries for the current organization and supports a user-confirmed custom title when no catalog entry matches. | `GET /fmea/job-catalog`, combobox and custom-title option |
| FR-FMEA-PROC-003 | Selecting a job refreshes related equipment, material and control suggestions. | Catalog relationship plus suggestion request |
| FR-FMEA-PROC-004 | Suggestions are advisory and require explicit selection; users can add missing items. | Selection chips, hidden confirmed arrays and create payload |
| FR-FMEA-PROC-005 | Changing the selected job clears stale suggestion state. | Frontend selection state and regression contract |
| FR-FMEA-PROC-006 | Job/process and activity description are required; other process fields are optional. | Client validation and API schema |
| FR-FMEA-PROC-007 | Description assistance is bounded to one or two sentences and, after the user requests it, is written directly into the editable activity-description field. | 1,200-character/two-sentence limit, sanitized response and direct field update |
| FR-FMEA-RISK-001 | The main FMEA register displays process/activity, failure mode, effect, cause, current controls, S/O/D, RPN, risk level and recommended action. | `fmea-risk-table` and server-calculated row fields |
| FR-FMEA-RISK-002 | The register supports search, risk filtering, numeric sorting, details, editing and confirmed deletion. | Toolbar, detail panel, item PATCH/DELETE routes and audit events |
| FR-FMEA-RISK-003 | The register provides client-side pagination for larger result sets and an S/O/D guide with a criterion for every score from 1 to 10. | Paginated table view, accessible score selectors and detailed guide |
| FR-FMEA-RISK-004 | When risk AI is available, bounded suggestions for failure mode, effect, cause and recommended action require explicit user selection and never mutate a row automatically. | Risk-row suggestion endpoint, bounded parser and accept-only UI |
| FR-FMEA-RISK-005 | The register exposes structured Excel (`.xlsx`) and real Word (`.docx`) exports in the authenticated panel; PDF report generation remains a backward-compatible API capability but is not offered as a panel download. | Panel export controls and compatibility route |
| FR-FMEA-RISK-006 | Adding a new FMEA risk row does not require manual row number or process-stage inputs; the API assigns the next row number and derives the process/activity context from the parent assessment when those legacy fields are omitted. | Add-row form and create-item API |
| FR-FMEA-RISK-007 | Each FMEA AI suggestion category displays three suggestions by default and provides an independent reversible plus/minus control for the remaining bounded suggestions. | Suggestion-assist component, accessible toggle and UI regression test |
| FR-FMEA-RISK-008 | The FMEA add/edit score panels keep S/O/D selectors, RPN preview and the calculate/save action aligned in one responsive control row, and selector criteria follow the supplied 1–10 reference scale. | Responsive score-panel layout, localized reference criteria and live RPN calculation |
| FR-FMEA-RISK-009 | The FMEA risk-row AI assist also returns advisory S/O/D score suggestions from the same row context; scores are shown after the score panel and are applied only after explicit user confirmation. | Structured AI score suggestion response, bounded 1–10 parser and accept/dismiss UI |
| FR-FMEA-RISK-010 | FMEA RPN classification follows the supplied reference bands: VERY_LOW 1–50, LOW 51–100, MEDIUM 101–200, HIGH 201–400 and CRITICAL above 400; the live score panel and reports use the same classification. | Shared risk-level helper, server recalculation, score-panel badge and report distribution boundaries |
| FR-FMEA-PROC-005 | The process-information step accepts up to five validated process/workplace images, starts bounded AI review automatically after upload, merges advisory risk rows into the editable review list, and stores each selected image after assessment registration. | Multi-image input, sequential image-analysis requests, editable review-row merge and tenant-scoped attachment uploads |
| FR-FMEA-REPORT-001 | The FMEA results page shows assessment header metadata, executive summary counts, risk-level distribution, top failure modes, NIVASafe suggestions and a corrective-action register. | `/fmea/:id/report` payload and report UI |
| FR-FMEA-REPORT-002 | Authorized users can register a manual corrective action, link it to an FMEA row, assign priority/status/owner and review it in the report. | `/actions` validation, row link migration and manual-action form |
| FR-FMEA-REPORT-003 | The report provides a collapsible complete FMEA table with S/O/D, AP, RPN and corrective actions, plus back and save operations; PDF is not exposed as a panel operation. | Full-details disclosure, save audit route and panel actions |
| FR-ASSESSMENT-PATH-001 | After authentication, users choose between FMEA and RULA from a clear RTL-aware method-selection surface with distinct descriptions and direct entry actions. | `/choose-path` cards and localized entry buttons |
| FR-ASSESSMENT-PATH-002 | The selected assessment method is remembered for the active browser session, while users can return from either assessment surface and change the method. | Session path key, change-method links and route contract tests |
| FR-ASSESSMENT-PATH-003 | The assessment-method selector remains responsive and keyboard accessible across desktop and mobile layouts. | Semantic buttons, focus treatment and responsive path-card styles |
| FR-RULA-PROC-001 | The RULA activity-information step captures job, task, optional occurrence duration, optional repetitions per shift, optional posture-hold duration, optional load/force and body-side context before scoring. Supplied duration measurements must include their unit. The project selector also offers project creation and returns with the new project selected. | RULA wizard process step, validated `activityInfo` payload and project-creation return flow |
| FR-RULA-PROC-002 | Users can optionally attach a posture photo with clear capture guidance; upload validation is tenant-scoped and restricted to supported image types and size. | Authenticated RULA attachment flow and image-signature checks |
| FR-RULA-PROC-003 | The activity context remains structured for a future AI posture-image capability without generating or persisting unverified AI imagery today. | Nullable `RulaAssessment.activityInfo` JSON and future-extension note |
| FR-RULA-PROC-004 | Users can optionally save a bounded, RULA-focused posture description and preview, replace, or remove the selected image before submission; repeated submission is prevented while the assessment is being registered. | `postureDescription` activity field, client image validation/lifecycle controls and guarded wizard submit |
| FR-RULA-ANALYSIS-001 | The posture-analysis step groups upper-limb and neck/trunk/leg results into reviewable tables with angles, detection state, suggested scores and per-row edit actions. | RULA Group A/B tables and posture-analysis contract |
| FR-RULA-ANALYSIS-002 | Users can correct posture values and the RULA score updates immediately from the edited scoring values before registration. | Editable posture dialog, shared RULA calculation and server-authoritative payload |
| FR-RULA-ANALYSIS-003 | The posture view preserves a reviewable image-analysis extension point with joint overlay metadata without claiming unsupported AI output. | `postureAnalysis` persistence and prepared image/joint overlay |
| FR-RULA-ANALYSIS-004 | AI-sourced posture values require explicit user confirmation; Group A/B totals, action level and the leading factor are derived from the current reviewed values. | Confirmation-aware posture contract, live group summary and action-level presentation |
| FR-RULA-REPORT-001 | A RULA results report shows the score, risk level, main neck/upper-arm/trunk factors with angles and contribution, and the selected assessment context. | `/rula/:id/report` read model and bilingual results view |
| FR-RULA-REPORT-002 | Assessors can select suggested corrective actions or add manual actions with priority and estimated score reduction. | RULA corrective-action cards, `CorrectiveAction.rulaImpact` and action API validation |
| FR-RULA-REPORT-003 | The predicted RULA score updates when corrective actions are selected or removed and is clearly labeled as a non-definitive prediction. | Dynamic report prediction and export summaries |
| FR-AUTH-001 | Registration always exposes personal and organization account-type choices, including when a recoverable draft exists, and rejects malformed persisted type values. | Accessible account-type radio group and normalized draft reader |
| FR-AUTH-002 | After successful credentials are verified, the user enters the authenticated panel directly with the first active organization membership returned by the server; users can switch among their authorized companies from inside the panel. | Direct login, server-returned membership persistence and in-panel company switcher |
| FR-AUTH-003 | Personal registration captures first name, last name, email, optional activity area, password and confirmation with client/server validation and a review step. | Existing registration wizard personal path and `/auth/register` validation |
| FR-AUTH-004 | Organization registration captures responsible-person, company and account details through visible wizard steps, preserves non-secret draft values across navigation, and shows a complete review before submission. | Existing registration wizard organization path |
| FR-AUTH-005 | Registration reports concise field-local Persian/English validation, validates mobile/email classification and company national-ID format, prevents duplicate submission, and shows a safe success or generic failure state. | Shared validators, API boundary, field error state and success destination |
| NFR-FMEA-PROC-001 | Catalog and assessment data are organization-scoped server-side. | `ensureJobCatalog`, project checks and permission checks |
| NFR-FMEA-PROC-002 | AI input/output is bounded and secrets remain server-side. | Prompt limits, output sanitization and provider boundary |
| NFR-FMEA-PROC-003 | Existing FMEA rows remain compatible and drafts survive refresh/offline interruption. | Nullable migration fields and autosave infrastructure |
| NFR-FMEA-PROC-004 | Persian uses RTL and English uses LTR with responsive form behavior. | Design rules and frontend implementation |
| NFR-AUTH-001 | Direct login cannot grant access: the client persists only a membership returned by the authenticated API, while the backend remains authoritative for role and organization scope. | Login response membership persistence and server-side `x-organization-id` authorization |
| FR-ORG-001 | An authenticated user can create and manage multiple independent organization workspaces, with a membership and role recorded separately for each workspace. | `POST /organizations`, `OrganizationMember`, organization management page |
| FR-ORG-002 | Each organization has an independent subscription plan/status/expiry; a newly created production organization remains blocked from operational routes until its own subscription is usable. | Organization subscription fields, checkout boundary and `SUBSCRIPTION_REQUIRED` guard |
| FR-ORG-003 | A user can switch between only the organization memberships returned by the server, and the selected organization is applied to subsequent tenant API requests. | Organization selector, `selectOrganization` and membership-scoped `authenticate` |
| NFR-ORG-001 | Organization users, settings, projects, assessments, actions, files, knowledge, notifications and AI usage remain isolated by organization scope. | Organization foreign keys, scoped queries/link validation and security review |
